# 测试与验收策略

状态：Review

P0 逐条标准见 [MVP P0 验收标准](p0-acceptance-criteria.md)，端到端业务行为见 [MVP 场景](../scenarios/mvp-end-to-end-scenarios.md)。

## 1. 测试层次

- 单元测试：状态转换、表达式、校验器、幂等和重试分类。
- 契约测试：事件、Capability、Skill、Workflow、Grant Schema 和版本兼容。
- 组件测试：每个脑区使用内存替身独立运行。
- 集成测试：EventBus、SQLite、Runtime 和 Fake Skill 的完整链路。
- 场景测试：用虚拟时钟重放一天市场时间线。
- 故障注入：超时、断连、非法输出、队列满、崩溃和重启。
- 长稳测试：持续运行 24 小时和 7 天。

## 2. 可测试性要求

- 所有时间判断使用注入的 Clock，不直接散落调用系统时间；
- 随机数可设置种子；
- LLM、行情和通知均有确定性 Fake；
- Workflow 执行能够捕获中间状态；
- 不依赖真实交易日等待测试；
- 每个故障有稳定错误码，而非只匹配错误字符串。

## 3. 必测场景

1. 09:25 到达时只触发一次竞价任务。
2. 重复快照、重复投递和重启不会重复通知。
3. LLM 返回非法 JSON、未知 Workflow 或越权 Capability 时被拒绝。
4. 子 Workflow 直接/间接递归时发布前失败。
5. Skill 卡死时节点和总任务按期限终止。
6. 队列满时行情合并，命令明确拒绝，任务结果不丢失。
7. 数据时间戳陈旧时不执行实时分析。
8. SQLite 短暂故障时停止新增副作用并进入降级模式。
9. 进程在外部调用前后分别崩溃时，恢复逻辑保持幂等。
10. 夜间 REVIEW 不运行实时扫描，但允许合法高优先级命令。
11. 达到 Token/费用预算后不再调用模型。
12. 日志和 Trace 中不存在测试密钥。

## 4. MVP 发布门槛

- P0 需求全部通过验收；
- 核心模块单元覆盖率目标不低于 85%；
- 关键状态机、RiskGate 和幂等路径分支覆盖率不低于 95%；
- 契约测试 100% 通过；
- 故障注入场景无进程冻结；
- 模拟环境连续 7 天无未解释的任务丢失和重复副作用；
- Critical/High 安全问题为零；
- 恢复演练和审计链检查通过。

## 5. 验收证据

每次里程碑需保存测试报告、指标快照、失败清单、恢复演练记录、费用统计和已知限制。仅以“能跑起来”不能视为完成。
