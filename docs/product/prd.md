# 产品需求文档（PRD）

状态：Review  
目标版本：MVP 0.1

最近评审：[MVP 需求评审记录（2026-08-16）](../reviews/requirements-review-2026-08-16.md)

## 1. 核心场景

### 场景 A：自动市场观察

系统持续接收模拟行情和时间信息。到达配置窗口或发生显著变化时，生成一次候选计划，执行市场分析 Workflow，并将结果写入记忆和报告。

### 场景 B：外部命令

用户通过受控入口要求“立即生成当前市场摘要”。命令进入同一事件通道，经过权限与计划校验后执行，不绕过治理流程。

### 场景 C：夜间复盘

市场关闭后，系统停止实时扫描，执行当日 Trace 汇总、失败分析和记忆压缩。外部高优先级命令仍可唤醒允许的任务。

### 场景 D：异常与恢复

当 LLM、工具、数据库或行情源异常时，系统记录故障、有限重试并进入相应降级模式；重启后恢复可恢复任务，过期任务直接终止。

### 2.1 产品交互与应用边界

MVP 面向单人量化研究者，采用本地 CLI，不开发 WebUI。生命周期和诊断命令属于平台运维入口；市场摘要、洞察查询、解释和通知偏好属于 `apps.quant_agent` 应用层。所有写命令必须进入 Command Adapter，经过事件、规划、RiskGate 和 Grant；查询只能读取带 snapshot/version 的投影，不得借查询接口产生业务副作用。

首批用户命令为 `start/status/stop`、`market summary`、`insights latest/show/explain` 和 `health`。洞察输出必须包含 `as_of`、freshness、evidence、risk notes、Workflow/Skill/data version 与 correlation ID；终端展示不得成为唯一事实源，JSON 是稳定机器接口，Markdown 是人类可读视图。

## 3. 非功能需求

- 响应性：事件循环不得执行无界阻塞调用。
- 可靠性：所有有副作用节点必须支持幂等键。
- 安全性：密钥不得写入消息、Prompt、Trace 或日志。
- 可审计：保存模型、Prompt、Workflow、工具及数据版本。
- 可演进：消息和 Workflow 均具有显式 schema/version。
- 成本：支持单次、单日 Token 与工具费用预算。
- 性能：MVP 单实例应支持至少 1000 条/分钟轻量事件输入，并通过合并控制推理频率。
- 数据治理：定义数据保留期限、摘要策略和删除机制。

## 4. 业务规则

1. 未注册的 Workflow、Capability 或未启用的 Skill 永远不可执行。
2. LLM 输出仅为候选计划，不具备直接执行权。
3. 过期事件和过期计划不得补执行时间敏感动作。
4. `SAFE_MODE` 下只允许读取、诊断和明确白名单内的恢复动作。
5. 计划触发必须同时满足日历、冷却期、幂等和预算限制。
6. 长期记忆必须带来源、置信度、适用范围和有效期。

## 5. MVP 用户故事

- 作为研究者，我希望系统在指定时间自动分析模拟行情，以便无需手动触发。
- 作为维护者，我希望看到每个任务为什么被触发以及执行了什么。
- 作为风险负责人，我希望未知工具、非法参数和超预算操作被确定性拒绝。
- 作为开发者，我希望新增一个 Workflow 不需要修改脑区之间的调用关系。
- 作为维护者，我希望服务重启后不会重复发送通知或执行过期任务。
- 作为研究者，我希望通过 CLI 获得最新市场摘要并查看证据、数据时间和风险，而不是读取内部日志。
- 作为研究者，我希望按 insight ID 查询和解释历史结论，并选择 JSON 或 Markdown 输出。

## 6. 产品指标

- 有意义事件与 LLM 调用比率；
- 计划接受、拒绝及拒绝原因分布；
- Workflow 成功率和 P50/P95 时延；
- 重复副作用次数；
- 恢复成功率；
- 每日模型调用量与费用；
- 记忆召回被采用率及事后正确率。
